# スマートフォンアクセス

## 構成と範囲

AndroidのChromeとPCへTailscaleを導入し、本人のTailnetからServeのHTTPS（443）を通してUniToDoへ接続します。本体の待受は`127.0.0.1:48120`、正本はPCのSQLiteです。Funnel、ポート開放、Exit Node、サブネットルーターは使いません。Tailscaleの接続管理サービスを利用しますが、DB同期は行いません。

PCはログオン済み・スリープなしで稼働させます。画面ロックは可能です。UniToDoはログオン起動のため、再起動後の未ログオン状態では利用できません。TailscaleのRun Unattendedだけではこの制約は解消しません。

独自ログイン画面、パスワード、OAuth/OIDC、Androidアプリ、オフライン保存、スマホ通知、競合解決用DB変更は含みません。既存の狭幅レイアウトとSSEを使用します。同時に同じ項目を編集すると後の保存で上書きされる場合があります。通信切断で保存結果が不明な場合は、再読込して確認してから再操作します。

## 信頼境界

- TailscaleのGrantで本人ユーザーから対象PCのTCP 443だけを許可します。端末承認を有効にし、紛失時は端末を失効します。認証元アカウントのMFAを推奨します。
- Grantと従来ACLの許可は加算されるため、初期の全許可ルールを残したまま限定ルールを足しません。本人ユーザーの他端末も対象になります。Androidへサーバー用タグは付けません。
- ローカル要求は実接続元がループバック、HTTP、Hostが`127.0.0.1:48120`または`localhost:48120`で、転送・Tailscaleヘッダーがない場合だけ許可します。
- Serve要求はループバック接続に加え、設定済みの正規Host、`X-Forwarded-Proto: https`、単一の本人`Tailscale-User-Login`を必須とします。情報が欠けた中継要求をローカル要求へ降格しません。
- Originがある場合は正規URLと一致させ、Serve経由の更新ではOriginを必須にします。更新には既存の`X-TaskManager-Request: local`も必要です。cross-site要求は原則拒否しますが、Androidのホーム起動に対応するため`GET /`と`GET /index.html`の最上位表示（`Sec-Fetch-Mode: navigate`、`Sec-Fetch-Dest: document`）だけを許可します。この例外でも本人・Host・Origin検証を維持し、API・更新・iframe・fetchは許可しません。CORSによる外部オリジン許可は追加しません。
- PC内のプロセスは引き続き信頼境界内です。ローカルプロセスによるヘッダー偽装まで防ぐ独自認証は追加しません。別のプロキシやHost書換えをこのポートへ追加しないでください。

## 設定と導入

1. PCとAndroidをTailscaleへ参加させます。
2. 管理者PowerShell 7で`pwsh -NoProfile -File ./scripts/configure-remote-access.ps1`を実行します。`-WhatIf`で書込前の確認が可能です。
3. `%LOCALAPPDATA%\TaskManager\remote-access.json`へ`serveOrigin`と`allowedLogin`、同じ場所の`tailscale-policy-proposal.json`へGrant全体案が生成されます。実値は端末内だけに保存し、Gitへ追加しません。このスクリプトは管理画面、Serve、HTTPS、Funnelを変更しません。
4. 管理画面で既存のアクセスルールを確認し、生成案を適用します。生成案は新規の専用Tailnet向けの全体案です。既存用途があるTailnetを無検査で置き換えず、必要なルールを維持して全許可との重複を解消します。生成されたpolicy testsが成功することも確認します。
5. 管理画面で端末承認を有効にし、PCとAndroidが承認済みであることを確認します。正規URLに個人情報を含めず、HTTPS証明書の有効化を行います。証明書のホスト名は公開CTログへ記録されます。
6. UniToDoを再起動して端末設定を読み込みます。発行・インストール時にも読み込まれます。不正または読取不能な設定では警告を記録し、リモートだけを無効にしてローカル運用を継続します。
7. 管理者ターミナルで`tailscale serve --bg http://127.0.0.1:48120`を実行します。HTTPSが未有効なら表示された公式設定URLを開いて設定します。Funnelの一般公開は有効にしません。
8. `tailscale serve status`と`tailscale funnel status`で、443の転送先が上記ループバックだけ、一般公開が無効であることを確認します。
9. AndroidでTailscaleを接続し、Serveが表示するHTTPS URLをChromeで開きます。必要ならホーム画面へ追加します。

端末設定は起動時に読み込むため、変更後はUniToDoの再起動が必要です。設定ファイルがない場合はリモート無効が既定です。通常の`/settings` APIから接続許可を変更できません。

## 操作範囲

| 操作 | Serve経由 |
|---|---|
| タスク、推薦、プロジェクト、作業時間、履歴、下書き承認 | 利用可能 |
| 予定キャッシュ表示・Calendar同期 | 利用可能 |
| 設定の読取 | 画面内部で使用 |
| 設定変更、Google資格情報登録・対話接続、バックアップ | APIで拒否 |
| Codex起動・音声レビューなど`/codex`配下 | APIで拒否 |

`GET /api/v1/access`は`remote`だけを返し、個人識別子は返しません。画面はServe経由の場合、設定タブとCodex起動ボタンを隠します。PC専用API拒否はURLの大文字小文字・末尾スラッシュでも維持します。Windowsの音声入力・通知はPC側の機能です。

## 検証と停止

- `scripts/test.ps1`：正規ローカル・Serve接続、設定なし、不正設定、別ユーザー、欠落・重複ヘッダー、不正Host/Origin、LAN直接接続、PC専用APIの拒否を検証します。
- 現環境：ローカル画面とCLIの互換、AndroidからのHTTPS表示・操作・SSE変更反映、画面復帰とWi-Fi/モバイル切替を確認します。実機確認が未実施なら完了扱いにしません。
- 403：端末設定の正規URL・本人、Origin、HTTPS経由、PC専用操作かを確認します。検査を削除して迂回しません。
- 接続不能：Tailscale接続・Grant・端末承認・鍵期限・Serve・PCのログオン/スリープを確認します。
- 停止：`tailscale serve --https=443 off`でこの入口を停止します。端末設定を削除してUniToDoを再起動すれば本体のリモート許可も無効になります。DBは変更しません。

公式資料：[Serve](https://tailscale.com/docs/features/tailscale-serve)、[Grant](https://tailscale.com/docs/reference/syntax/grants)、[Android](https://tailscale.com/docs/install/android)、[HTTPS](https://tailscale.com/docs/how-to/set-up-https-certificates)。
