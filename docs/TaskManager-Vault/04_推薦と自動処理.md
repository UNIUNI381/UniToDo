# 推薦と自動処理

## 推薦候補

候補は`実行可能`または`実行中`で、検証エラーがなく、開始可能日時を過ぎ、すべての先行タスクが完了しているタスクです。分割不可タスクは現在の空き時間へ収まる必要があります。

- `requiredContext`は現在保存・表示だけを行い、推薦除外には使わない。
- 空き時間が既定15分未満なら新規タスクを推薦しない。
- 推奨時間は残時間、最大作業時間、次の予定までの空き時間から5分を残して決める。

推薦再計算は完了・中止タスクの本文を読み込まず、依存条件に必要な完了済みIDだけを補います。計算結果の保存は変更行と候補から外れた行に限定します。実行中タスクの定期確認は状態索引で対象を絞ります。

## 期限集中の評価

1. 後続タスクの最も早い期限を先行タスクへ伝播し、実効期限を求める。
2. 同じ期限時刻の未完了作業をまとめ、早い期限から必要時間を累積する。
3. 各タスクの残時間へ既定20%の予備時間を加える。
4. 活動時間とGoogle予定前後の既定10分余白から、期限までの作業可能時間を求める。
5. `余裕時間 = 作業可能時間 - 累積必要時間`として期限リスクを計算する。リスクの正規化幅には当該期限時刻で追加される作業量を使い、前の期限群の作業量を後ろの期限群へ重複反映しない。
6. 目安期限のリスクは厳守期限の75%に抑える。

この処理により、同じ日に複数の締切が集中する場合も個別タスクではなく期限群全体の負荷を評価します。

## 優先度スコア

各要素を0～1へ正規化し、設定された重みの合計で割った相対加重平均を0～100へ変換します。

| 要素 | 既定重み | 概要 |
|---|---:|---|
| 期限リスク | 0.45 | 実効期限までの累積余裕 |
| 重要度 | 0.25 | 重要度1～5 |
| 後続解放 | 0.10 | 直接後続タスク数 |
| 延期 | 0.10 | 延期・中断回数 |
| 継続性 | 0.10 | 実行中なら加点 |
| 経過 | 0.10 | 開始可能日からの経過と重要度 |

経過スコアは線形増加し、重要度1は45日、3は30日、5は15日で最大になります。開始可能日がない旧データは登録日時を使います。

## 最終選択順

1. 累積厳守期限が既に不足している候補
2. 実行中タスク
3. 先の期限に必要な余裕を壊さない候補
4. 全候補

各集合内は優先度スコア降順、実効期限昇順、登録日時昇順です。目安期限だけの不足では実行中タスクを差し替えません。

## 依存と状態遷移

- タスク完了時、すべての先行タスクが完了した後続タスクの開始可能日を解放日時へ更新する。
- 明示された未来の開始可能日は早めない。
- 先行タスク中止時、後続は依存達成にせず`要確認`へ送る。
- 開始時は他の実行中タスクまたは自由活動を終了・中断し、単一タイマーを維持する。
- 完了、中断、延期、中止は関連作業ログを同じ保存処理で閉じる。実績時間は残時間から自動減算しない。
- 実行中ログの開始時刻修正では、タスクの開始時刻、完了確認予定、長時間警告予定を同じ差分だけ移動し、ログと同じトランザクションで保存する。

## 常駐処理

`AutomationWorker`は起動直後と1分ごとに次を判定します。

| 処理 | 周期・条件 |
|---|---|
| Calendar同期 | 認証済みなら5分以上の間隔。失敗時はキャッシュ維持 |
| CodexのCalendar操作後 | 専用会話のCalendarツール成功で追加同期。待機中の要求を集約し、予定・推薦更新後に画面通知 |
| 長時間警告 | 既定180分でPC通知 |
| 自動停止 | 警告後60分間無操作なら警告時刻基準で停止し要確認化 |
| 朝通知 | 設定時刻以降の当日最初の推薦を1回 |
| 完了確認 | 推奨時間＋猶予10分を過ぎた実行中タスクへ1回 |
| 操作履歴整理 | 起動時と日付変更後。バックアップ後に90日より古い履歴を削除。失敗時は次周期に再試行 |
| バックアップ | 当日未作成なら1回 |
| 追加バックアップ | 有効時、時間別は直近の確認成功から1時間以上、日別は当日未確認なら比較し、変更時だけ保存。初回・保存先変更後は次周期で作成 |

通知台帳の一意キーで重複を防ぎ、通知無効時も推薦・同期・自動停止・バックアップは継続します。

追加バックアップは`ExternalBackupService`が他の自動処理より先に実行します。正本DBだけをSQLiteオンラインバックアップで一時ファイルへ複製・整合性検証し、時間別・日別それぞれの直近世代と構造・全テーブルの値を比較します。文字の大小・NULL・型も区別し、物理配置や内部更新カウンターだけの差は除外します。同じ内容なら一時ファイルだけを回収し、完成世代を増減させません。内容が変わった場合だけディスクへ反映して完成名へ変更し、時間別6世代・日別30世代へ整理します。

変更なしも確認成功として区分ごとの確認時刻を進め、毎分の再比較を避けます。確認時刻・結果はメモリに保持し、再起動時は完成名のUTC保存日時を基準に再確認します。日別の境界はPCのローカル日付です。稼働していなかった時間・日を遡って補完しません。手動実行は時間別を即時比較し、変更があれば時間別世代に含みます。当日確認済みの日別世代は増やしません。

失敗は成功扱いせず次の1分周期で再試行し、設定画面へエラーと最後に保存できた時刻を返します。自動・手動の保存は排他制御します。OFFでは保存先へのアクセス・削除を行わず、保存先変更でも旧フォルダは保持します。完成ファイルだけを整理し、管理外ファイルは削除しません。既存の本体内30世代は独立して継続します。
