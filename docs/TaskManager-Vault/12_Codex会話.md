# Codex会話

## 構成

入力欄はEnterで改行し、IME変換中を除くCtrl+Enterまたは送信ボタンで本文を送信します。
入力欄の上に「送信できます」などの会話状態を表示します。通常の履歴再取得は「履歴を更新しました」と通知して約3秒後に閉じます。直前に送信結果が不明だった場合だけ反映状況の確認を促す注意を添え、注意は残します。実際のエラーは表示を維持し、エラーのない完了状態へ復帰した場合は約3秒後に閉じます。成功通知はサーバーのエラー状態へ保存しません。
パネルはPCで欄外から押し始めたときだけ閉じます。パネル内から欄外へドラッグしても閉じません。

PCとAndroidの「Codexでタスク管理」は、UniToDo内の同じ専用会話を開きます。PCでは右パネル、スマホでは全面表示です。PC幅（681px以上）ではパネル外のクリックでも閉じます。パネル内と「Codexでタスク管理」ボタンのクリックでは閉じません。閉じても入力内容・会話・実行は保持し、表示用ポーリングだけを停止します。外部のCodexアプリへ移動せず、本文送信、逐次応答、質問への回答、今回のみの実行承認・拒否、停止、履歴再取得、新しい会話を扱います。履歴は末尾200項目、各本文は最大64,000文字を表示します。独自ターミナルや任意RPCは公開しません。Androidでは`interactive-widget=resizes-content`でキーボード表示時にViewportを縮小し、`visualViewport`の高さ・位置変更にもパネルを追従させます。開いた直後と入力中は最新の発言を表示し、縦幅が狭い場合は入力領域をコンパクトにします。

`assistant.js` → `/api/v1/assistant` → `CodexChatService` → `ICodexAppServer` → `codex app-server --listen stdio://`で接続します。App Serverのネットワーク待受は作りません。既存のPC側Codex CLIとChatGPTログインを利用し、OpenAI APIや独自の認証情報保存は追加しません。モデルは音声送信と同じ`gpt-5.6-luna`、推論は`low`、サービスティアは`fast`です。検証したCLIは0.146.0です。プロトコル変更時はインストール済みCLIの`generate-json-schema`と公式資料で互換性を確認します。

## 実行と保存

- 会話はアプリ専用の1件を自動作成・復元します。「新しい会話」で切り替え、古い履歴はCodex側に残します。音声入力もこの会話を使用し、旧音声用送信先IDは使用しません。デスクトップアプリの他会話とは分離します。
- 接続先がアーカイブ済みの場合は`archived`状態と会話識別子を画面へ返し、送信・停止を無効、新しい会話を有効にします。アーカイブ解除や自動切替は行わず、利用者の新規作成操作で復旧します。復元・送信・履歴取得のアーカイブ専用エラーと対象会話のアーカイブ通知を扱い、一般的な通信障害とは区別します。表示用ポーリングで復元を繰り返さず、明示的な履歴再取得では外部からのアーカイブ解除を確認できます。
- 同時実行は1件です。本文は20,000文字以内。同じ送信識別子と同じ内容は再実行せず、同じ識別子の別内容や古い画面からの会話違いは拒否します。重複防止記録は送信前に保存し、1会話1,000件に達したら新しい会話へ切り替えます。
- `%LOCALAPPDATA%\TaskManager\codex-chat-state.json`は会話識別子と受付ID・本文ハッシュだけを保存します。会話本文はCodexのローカル履歴に保存されます。アプリDB、Vault、アプリログへ本文を保存しません。ブラウザの履歴キャッシュは無効にします。
- 表示中は約1.2秒ごとに状態を取得します。ブラウザを閉じても処理を継続します。PCアプリ終了時は所有するApp Serverを停止します。再起動時は同じCodex会話を復元します。
- 送信結果が不明なときは自動再送しません。「履歴を再取得」で既存会話を照合します。停止は実行済みの変更を取り消す機能ではありません。最終結果とタスク画面の状態を確認します。

## Calendar操作後の同期

専用会話の`codex_apps`による`google_calendar.`または`google_calendar_`で始まるMCPツールが成功すると、会話の完了を待たず既存の読取専用Calendar同期を要求します。作成・更新・削除と読取操作を対象とし、送信文や回答本文から操作を推測しません。`item/completed`と`turn/completed`の項目を照合し、同じ項目IDの二重通知、失敗・拒否、別会話・別実行の通知、履歴再表示では同期を増やしません。会話全体が中断・失敗しても、既に成功したCalendar操作は同期対象です。

`CalendarSynchronizationQueue`は待機要求を1件にまとめ、`CalendarSynchronizationWorker`が本体の認証済みカレンダーを同期します。同期中の追加要求は次回分に保持します。定期・手動同期と同じサービスのロックを使い、同期成功後に推薦を更新し、SSEでPC・Androidの表示へ反映します。会話の応答と同期通信は独立し、パネルを閉じても継続します。本体のCalendar接続が未設定ならスキップし、同期失敗ではキャッシュを保持して既存の同期エラー表示を更新します。同期対象のカレンダーと期間は本体設定に従い、プラグイン側の操作対象に合わせて設定を変更しません。

## 権限と確認

本体の待受は`127.0.0.1:48120`です。Androidの会話APIにも既存のServe本人情報・Host・Origin・更新ヘッダー検証を適用します。旧`/api/v1/codex`のWindows用操作は引き続きリモートから拒否します。

作業場所はデータ領域内の`assistant-workspace`に固定します。`workspace-write`サンドボックスと`never`承認を新規作成・復元・各送信で指定します。書込み範囲は専用作業場所、CLI配置先、標準の一時領域です。正本DB領域や開発リポジトリは追加せず、ネットワーク制限を維持します。通常のtaskctl実行は承認不要とし、権限不足は確認を出さず拒否します。ブラウザから作業場所・モデル設定・任意コマンド・任意会話IDを指定できません。タスク操作は同梱した`assistant-skill/SKILL.md`を使い、専用PATHの`taskctl`を直接実行するよう指示します。`shell_environment_policy.set.PATH`は同梱CLI配置先を先頭にし、子シェルだけに適用します。利用者全体のPATHは変更しません。送信ごとに`app/installed`を専用会話の`threadId`と`forceRefresh: true`で呼び、`enabled`かつ`callable`の接続アプリだけを`app://`のmentionとして渡します。キャッシュの場所・版・ローカルSKILL.mdの有無や、送信文のキーワードで連携を選別しません。利用する連携は本文と会話履歴からモデルが判断し、無関係な連携は呼ばないよう指示します。本文は改変せず、明示スキル入力は同梱タスク操作スキルだけです。本体のGoogle Calendar同期に対する`calendar.readonly`と、明示依頼による接続プラグイン経由の予定登録・更新・削除を区別します。接続情報の取得失敗や不正応答では本文を送信せず、受付IDも消費しません。実際に接続アプリが空の場合は通常会話を継続します。無効・呼出不能なアプリは投入せず、個別アプリの権限設定を上書きしません。JSON入力には`--file -`、読取には`--fields`と`get ID`を使えます。スキルの指示はOSの権限制限とは別です。CLI実行可否の確認は省略しますが、対象の曖昧さ、削除、プロジェクト変更などスキルで定める業務上の確認は維持します。

コマンド実行・ファイル変更・追加権限の承認と、Codexの質問への回答を扱います。承認は保存済みの要求内容に対して今回だけ返信し、永続的な許可ルールを作りません。複数端末からの回答は最初の1件だけを採用します。終了・切断した確認へは回答できません。外部MCPの標準`form`は、空の確認フォームと文字列・真偽値・文字列選択肢の入力を表示し、「今回のみ許可」「拒否」を返します。回答は保存済みスキーマで必須項目・型・選択肢・未知の項目を再検証し、既定値による自動承認を行いません。空フォームの承認は`action: accept, content: {}`、拒否は`content: null`です。URL認証、拡張`openai/form`、未対応の制約を含むフォームは引き続き承認せず、拒否または停止を案内します。応答は確認ごとに1回限りで、切断・完了後の承認や永続許可を作りません。

## 音声入力との境界

F13 → TypeWhisper → Ollama → Windows確認画面 → `CodexVoiceChatRunner` → `CodexChatService` → `CodexAppServer`でWebと同じ会話へ送信します。確認前は本文を送らず、録音開始後に共有会話の準備だけを行います。音声の完了応答はWindows状態画面にも表示し、追加質問・承認・停止・履歴確認はWeb UIで操作します。送信識別子と単一実行制御を共有し、受付後の失敗・結果不明は音声確認キューへ戻しません。

## 検証

通常テストは偽App Serverで二重送信、単一実行、接続アプリの実行可否・重複除外・単語に依存しない追送・無効化の反映・取得失敗時の未送信と再送、アーカイブ後の明示新規作成・再接続・旧画面拒否・遅延通知、MCP確認の明示承認・拒否・スキーマ検証・未対応形式拒否、承認の二重回答、未回答質問、停止、永続化、結果不明の再照合、切断、所有外会話の除外を検証します。Calendar操作後の同期では、作成・更新・削除・読取の成功、失敗・拒否の除外、項目通知と実行完了通知の重複防止、中断後の成功操作、履歴再表示の除外、同期要求の集約・次回分保持を検証します。Serveの会話送信・承認APIも本人・Originの正常系と拒否系を検証します。

任意の実接続試験はテスト実行ファイルの`--codex-smoke`です。既存CLIログインでツールを使わない接続確認だけを送り、応答と履歴取得を検査します。`--codex-task-smoke`は`taskctl list --fields identifier`を直接実行し、本文を出力せずJSON解析成功と承認不要を検証します。データ変更は行いません。`--codex-calendar-smoke`はGoogle Calendarの`get_colors`だけを実行し、App Serverのツール完了通知で接続を確認します。予定や個人情報は取得・変更しません。通常テストはCodexへの通信や実タスク操作を行いません。Androidのホーム起動、文字入力、回線切替後の確認待ち復帰は実機で確認します。
