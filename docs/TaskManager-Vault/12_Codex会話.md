# Codex会話

## 構成

PCとAndroidの「Codexでタスク管理」は、UniToDo内の同じ専用会話を開きます。PCでは右パネル、スマホでは全面表示です。外部のCodexアプリへ移動せず、本文送信、逐次応答、質問への回答、今回のみの実行承認・拒否、停止、履歴再取得、新しい会話を扱います。履歴は末尾200項目、各本文は最大64,000文字を表示します。独自ターミナルや任意RPCは公開しません。Androidでは`interactive-widget=resizes-content`でキーボード表示時にViewportを縮小し、`visualViewport`の高さ・位置変更にもパネルを追従させます。開いた直後と入力中は最新の発言を表示し、縦幅が狭い場合は入力領域をコンパクトにします。

`assistant.js` → `/api/v1/assistant` → `CodexChatService` → `ICodexAppServer` → `codex app-server --listen stdio://`で接続します。App Serverのネットワーク待受は作りません。既存のPC側Codex CLIとChatGPTログインを利用し、OpenAI APIや独自の認証情報保存は追加しません。モデルは音声送信と同じ`gpt-5.6-luna`、推論は`low`、サービスティアは`fast`です。検証したCLIは0.146.0です。プロトコル変更時はインストール済みCLIの`generate-json-schema`と公式資料で互換性を確認します。

## 実行と保存

- 会話はアプリ専用の1件を自動作成・復元します。「新しい会話」で切り替え、古い履歴はCodex側に残します。音声用の送信先ID、デスクトップアプリの他会話とは分離します。
- 同時実行は1件です。本文は20,000文字以内。同じ送信識別子と同じ内容は再実行せず、同じ識別子の別内容や古い画面からの会話違いは拒否します。重複防止記録は送信前に保存し、1会話1,000件に達したら新しい会話へ切り替えます。
- `%LOCALAPPDATA%\TaskManager\codex-chat-state.json`は会話識別子と受付ID・本文ハッシュだけを保存します。会話本文はCodexのローカル履歴に保存されます。アプリDB、Vault、アプリログへ本文を保存しません。ブラウザの履歴キャッシュは無効にします。
- 表示中は約1.2秒ごとに状態を取得します。ブラウザを閉じても処理を継続します。PCアプリ終了時は所有するApp Serverを停止します。再起動時は同じCodex会話を復元します。
- 送信結果が不明なときは自動再送しません。「履歴を再取得」で既存会話を照合します。停止は実行済みの変更を取り消す機能ではありません。最終結果とタスク画面の状態を確認します。

## 権限と確認

本体の待受は`127.0.0.1:48120`です。Androidの会話APIにも既存のServe本人情報・Host・Origin・更新ヘッダー検証を適用します。旧`/api/v1/codex`のWindows用操作は引き続きリモートから拒否します。

作業場所はデータ領域内の`assistant-workspace`に固定します。`workspace-write`サンドボックスと`never`承認を新規作成・復元・各送信で指定します。書込み範囲は専用作業場所、CLI配置先、標準の一時領域です。正本DB領域や開発リポジトリは追加せず、ネットワーク制限を維持します。通常のラッパー実行は承認不要とし、権限不足は確認を出さず拒否します。ブラウザから作業場所・モデル設定・任意コマンド・任意会話IDを指定できません。タスク操作は同梱した`assistant-skill/SKILL.md`を使い、`invoke-taskctl.ps1`経由で行うよう指示します。スキルの指示はOSの権限制限とは別です。スクリプト実行可否の確認は省略しますが、対象の曖昧さ、削除、プロジェクト変更などスキルで定める業務上の確認は維持します。

コマンド実行・ファイル変更・追加権限の承認と、Codexの質問への回答を扱います。承認は保存済みの要求内容に対して今回だけ返信し、永続的な許可ルールを作りません。複数端末からの回答は最初の1件だけを採用します。終了・切断した確認へは回答できません。外部MCPの特殊フォームやログイン確認はこの画面で承認せず、拒否または停止を案内します。自動承認で迂回しません。

## 音声入力との境界

F13 → TypeWhisper → Ollama → Windows確認画面 → `codex exec resume`は維持します。Webの`CodexChatService`はHTTPやWinFormsに依存しない送信・回答・停止の契約を持つため、将来は音声の確認済み本文を`ChatSubmission`へ変換して同じ経路へ接続できます。現時点では音声入力の送信先設定を変えてもWeb会話には影響しません。

## 検証

通常テストは偽App Serverで二重送信、単一実行、承認の二重回答、未回答質問、停止、永続化、結果不明の再照合、切断、所有外会話の除外を検証します。Serveの会話送信・承認APIも本人・Originの正常系と拒否系を検証します。

任意の実接続試験はテスト実行ファイルの`--codex-smoke`です。既存CLIログインでツールを使わない接続確認だけを送り、応答と履歴取得を検査します。`--codex-task-smoke`はラッパーで一覧を読取り、本文を出力せずJSON解析成功と承認不要を検証します。データ変更は行いません。通常テストはCodexへの通信や実タスク操作を行いません。Androidのホーム起動、文字入力、回線切替後の確認待ち復帰は実機で確認します。
