# 開発運用

## 環境

- Windows 10または11
- .NET 10 SDK。`global.json`は.NET 10.0.11のセキュリティ修正を含む`10.0.303`を最低版とし、同じ10系の最新Feature Bandへロールフォワード
- 全プロジェクトは`net10.0-windows`、警告をエラー扱い、lockファイルを使用
- ワークスペース内`.dotnet`を優先し、なければPATH上の.NET 10を使用
- ビルドと全テストはWindows PowerShell 5.1とPowerShell 7の両方に対応し、日本語を含むPowerShellスクリプトは5.1で誤解釈されない文字コードを維持する
- 発行・インストール・頒布ZIP生成はPowerShell 7（`pwsh`）を明示して実行する。Windows PowerShell 5.1の`powershell`では実行しない。5.1には`System.IO.Path.GetRelativePath`がなく、発行時のライセンス収録や頒布時のallowlistコピー処理で停止する

## 標準コマンド

| 目的 | コマンド |
|---|---|
| ビルド | `./scripts/build.ps1` |
| 全テスト・静的検査 | `./scripts/test.ps1` |
| 自己完結発行 | `pwsh -NoProfile -File ./scripts/publish.ps1` |
| 上書きインストール | `pwsh -NoProfile -File ./scripts/install.ps1` |
| アンインストール | `./scripts/uninstall.ps1`。監視タスク、実行物、ショートカット、PATH登録を削除し、ユーザーデータは保持 |
| 個人データ検査済み頒布ZIP | `pwsh -NoProfile -File ./scripts/create-distribution.ps1`。詳細は[頒布と受取人セットアップ](08_頒布と受取人セットアップ.md) |
| TypeWhisper連携の確認・導入 | `./scripts/install-typewhisper-integration.ps1 -WhatIf`、同スクリプトの通常実行。詳細は[音声入力](07_音声入力.md) |
| 開発ツリーからCLI | `./scripts/task.ps1 <command>` |
| スマホ接続の端末設定を準備 | 管理者PowerShell 7で`./scripts/configure-remote-access.ps1`。Serve・Grantは変更しない |

発行先は `artifacts/publish/TaskManager`、導入先は `%LOCALAPPDATA%\Programs\TaskManager`。自己完結型 `win-x64` で、利用PCの別ランタイムは不要です。`install.ps1` は内部で発行するため、先に発行済みなら `-SkipPublish` を使います。

ライセンス収録は[ライセンスと第三者コンポーネント](10_ライセンスと第三者コンポーネント.md)、第三者向けZIPと公開は[頒布と受取人セットアップ](08_頒布と受取人セットアップ.md)を参照してください。

## 変更時の参照

共通規則と変更規模は [AGENTS.md](../../AGENTS.md)、検証・現環境反映・記録の流れは [開発Skill](../../.agents/skills/update-task-manager-system/SKILL.md) に集約します。以下は対象変更時だけ適用します。

- DB：新しい版のマイグレーションを追加し、適用直前のバックアップと旧DBからの移行を検証する。既存マイグレーションを書き換えず、実DBを手作業で修正しない。
- 画面：HTML・JavaScript・CSSの整合と静的資産クエリ版を確認する。
- 業務規則：UI・API・CLIの共通処理は既存Serviceへ置く。同時更新は既存の操作ロックとSQLiteトランザクションに合わせる。
- 操作Skill：正本は `.agents/skills/manage-local-tasks`。本体の `assistant-skill` と利用中のユーザーSkillには変更ファイルだけを同期できる。コピー先に独自変更があれば上書き前に差分を確認する。

## テスト観点

標準検証に加え、変更に関係する項目だけを選びます。全項目の手動検証を毎回行う必要はありません。

- リモート接続：ローカルCLI互換、Serveの本人・Host・Origin・転送ヘッダー、未設定時の拒否、PC固有API拒否。導入後はAndroidでHTTPS・回線切替・SSE復帰を確認する。手順は[スマートフォンアクセス](11_スマートフォンアクセス.md)。
- 推薦：期限集中、厳守割込み、重要度、経過、継続性、予定余白、5,000件性能
- 依存：欠落、循環、開始可能日、親自動完了、中止時要確認
- 下書き：仮参照、冪等性、コミット前失敗、保存後警告
- プロジェクト：正規化、別名、あいまい候補、背景有効期間、既定期限、色
- 作業時間：単一タイマー、切替、警告、自動停止、重複、境界、10,000件集計
- Calendar：キャッシュ継続、安全な埋め込みURL
- ライセンス：lockファイルと依存一覧の一致、頒布時の発行依存一致、SDK付属文書と各実行時パッケージ付属文書の同梱・ハッシュ一致
- Codex音声入力：[音声入力](07_音声入力.md)のテスト観点を参照する。
- CLI：標準入力とファイル入力の互換、部分更新の省略・null、日本語・引用符、項目選択のネスト・配列・null、不正オプションでの更新防止。
- Codex Web会話：[Codex会話](12_Codex会話.md)の二重送信・承認・復旧テストと任意の実接続試験を参照する。

スマホスワイプ変更時はNode.jsで`node --test tests/mobile-navigation.test.cjs`も実行し、方向・閾値・縦スクロール・入力・横スクロール・画面端・複数指・非表示タブ・中断を検証します。実機ではAndroidの戻る操作やカレンダー横移動との競合を確認します。
会話パネルの履歴操作変更時は`node --test tests/assistant-navigation.test.cjs`で戻る・進む、入力保持、開閉の重複と非同期競合、PCの履歴非変更を確認します。AndroidのChromeホーム起動では、戻る操作で会話だけが閉じることと、キーボード表示時の挙動を実機で確認します。
タスク開始UIの変更時は`node --test tests/task-start.test.cjs`も実行し、活動別の切替、キャンセル、同一タスク、二重クリック、活動変更、終了失敗時の開始抑止を検証します。

発行後の標準入力検査は`tests/Test-CliStdin.ps1 -ExecutablePath <発行済みtaskctl.exe>`をPowerShell 7と5.1の両方で実行します。UniToDo起動中に日本語のBOMあり・なしを検証し、不正JSONを送るため更新APIには到達しません。実接続試験の配置先は通常ユーザー所有にします。サンドボックスユーザー所有の一時配置ではCodexのACL設定に失敗する場合があります。

## 障害切り分け

| 症状 | 確認先 |
|---|---|
| 画面が古い | 静的資産クエリ版、配布物、インストール先、キャッシュ無効応答 |
| CLI接続失敗 | アプリ起動、`/api/v1/health`、固定ポート |
| DBロック | `busy_timeout`、長い接続、Service外の直接接続 |
| Calendar失敗 | credentials、DPAPIトークン、最終同期エラー、キャッシュ |
| 推薦が空 | 状態、開始可能日、依存、検証結果、現在空き時間 |
| タイマー不整合 | 単一実行索引、起動時整合処理、関連タスク状態 |
| アプリ停止 | Windowsタスク`UniToDo Watchdog`の状態・最終結果、Windows復旧通知、ダッシュボードの未確認警告、`%LOCALAPPDATA%\TaskManager\logs`の`watchdog-*.log`・`watchdog-crash-*.log`・`crash-*.log`・`recovery-*.log`・`latest-system-incident.json`、監視親と本体の開始・終了、再起動結果 |
| 音声入力・Codex送信 | [音声入力](07_音声入力.md)の障害切り分け表 |
