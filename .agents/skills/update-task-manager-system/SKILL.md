# Task Managerシステム更新

日常のタスク操作には`manage-local-tasks`を使い、このSkillは開発変更だけに使用する。

## 開始時

1. [AGENTS.md](../../../AGENTS.md)を確認する。
2. Vaultの[入口](../../../docs/TaskManager-Vault/00_入口.md)と変更対象のノートを読む。
3. [開発運用](../../../docs/TaskManager-Vault/06_開発運用.md)と[ローカルGit管理](../../../docs/TaskManager-Vault/09_ローカルGit管理.md)を読む。
4. `git status --short --ignored`で既存変更、未追跡物、除外物を把握し、ユーザーの変更を作業対象から分離する。

## 完了条件

- ソース、DBマイグレーション、テストを正本として変更し、同じ作業でVaultの関連ノートを現在仕様へ合わせる。
- Vaultは古い説明を置き換え、変更履歴やソースの逐語的な転載を残さない。実タスク、顧客、予定、作業ログ、資格情報、トークン、DB、バックアップの内容を書かない。
- 検証は[開発運用](../../../docs/TaskManager-Vault/06_開発運用.md)に従い、少なくとも`scripts/test.ps1`を実行する。配布変更では同ノートの追加検証も行う。
- Git操作は[ローカルGit管理](../../../docs/TaskManager-Vault/09_ローカルGit管理.md)に従う。対象ファイルを明示してステージし、`git diff --check`、ステージ済み一覧・内容、追跡漏れ、除外対象や秘密情報の混入を確認する。
- 検証済みの実装、テスト、Vaultを一つの変更単位としてローカルコミットする。ユーザーがコミット不要または作業途中と指定した場合はコミットせず、未記録の状態を明示する。
- リモートの追加、push、公開はユーザーが明示した場合だけ行う。
- 既存のユーザー変更と安全に分離できない場合は、そのファイルをステージまたはコミットせず状況を報告する。

完了時は、検証結果、更新したVault、Gitの状態、コミットした場合はコミットIDを簡潔に報告する。
