# UniToDoシステム更新

## 着手と実装

1. [AGENTS.md](../../../AGENTS.md)に従い、`git status --short`で既存変更を確認する。追跡・除外の詳細が必要な場合だけ `--ignored` を付ける。
2. [Vaultの入口](../../../docs/TaskManager-Vault/00_入口.md)から変更に関係するノートを読む。環境・検証は[開発運用](../../../docs/TaskManager-Vault/06_開発運用.md)を参照する。
3. 依頼を満たす最小限の変更を実装し、影響するVaultを更新する。将来用の仕組みや無関係な整理を追加しない。

## 検証と現環境への反映

- `scripts/test.ps1`を実行する。追加検証は変更した挙動・境界・失敗経路に絞り、実装の写しや文言一致だけを検査するテストを増やさない。新しい変更・失敗・未解決の懸念がなければ同じ検証を繰り返さない。
- インストール済み本体・CLIへの反映が必要なら、PowerShell 7で `pwsh -NoProfile -File ./scripts/install.ps1` を実行する（内部で発行する）。発行だけなら `publish.ps1`、検証済み発行物の導入だけなら `install.ps1 -SkipPublish` を使う。導入後は `127.0.0.1:48120` で起動と変更箇所を確認する。Windows PowerShell 5.1では発行・インストールしない。
- 文書だけの変更では本体を再インストールしない。操作Skillの変更は利用中のコピーへ必要なファイルだけ反映し、一致を確認する。ユーザーがソース変更のみ・反映不要と指定した場合は反映しない。
- 第三者向け頒布ZIPは、ユーザーが生成を明示した場合だけ `scripts/create-distribution.ps1` で作成・検査する。頒布対象ファイルの変更だけでは生成しない。

## 記録と報告

- [ローカルGit管理](../../../docs/TaskManager-Vault/09_ローカルGit管理.md)に従い、検証済みの変更をローカルコミットする。ユーザーがコミット不要・作業途中と指定した場合はコミットしない。
- 既存のユーザー変更と安全に分離できないファイルはステージせず報告する。リモート追加・push・公開は明示依頼時だけ行う。
- 完了時は変更点、検証結果、現環境への反映、Vault・Gitの状態とコミットIDを簡潔に報告する。
