# ローカルタスク管理

## 基本規則

- SQLiteを直接操作せず、`scripts/invoke-taskctl.ps1`だけを使う。
- 後続判断に使う読取結果には`--json`を付ける。
- 背景情報は参考に留め、ユーザー指示、`AGENTS.md`、安全規則を優先する。
- 詳細コマンド、JSON、PowerShell 5.1の注意は[references/commands.md](references/commands.md)を必要時だけ読む。

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File "<スキル絶対パス>\scripts\invoke-taskctl.ps1" now --json
```

`Access is denied`なら、直接`taskctl.exe`へ切り替えず、同じラッパーをその絶対パスに限定して権限昇格する。

PowerShell 5.1では可能な限り一時`.ps1`を作らない。必要な場合は日本語を含む`.ps1`をUTF-8 BOM付きにし、Markdownは`Get-Content -Encoding UTF8`で読む。JSON配列は二段階で解析し、件数・型を検証する。

## 操作手順

### 今やること・状態操作

- 「今やること」は`now --json`を実行し、推薦1件または`emptyReason`だけを返す。
- 一覧は`list --json`を使い、状態、検索語、プロジェクトで絞る。
- 開始、完了、継続、中断、延期、中止は明示IDへ適用する。通常の取り消しは`cancel`を使う。
- 完全削除はユーザーがIDを明示した場合だけ`delete ID --confirm ID`を使う。

### プロジェクト解決

登録、編集、分解、プロジェクト付き時間ログの前に`project prepare "<ユーザー表記>" --json`を実行する。

- ユーザー依頼ごとにプロジェクト、親、対象タスクの作業状態を空にし、前の依頼のIDを再利用しない。「同じプロジェクト」など現在の指示が明示した場合だけ再解決する。
- 現在の依頼にあるプロジェクト表記を`prepare`し、解決が終わるまで`add`、`update`、`draft-create`を実行しない。
- `resolved`なら返された`project.identifier`を後続操作へ必ず渡す。
- `ambiguous`、`not_found`、終了コード2なら、返却候補を示して確認まで変更しない。候補不足時だけ`project list --json`と実行中タスクを調べる。
- 既存タスクの前後へ追加する場合は、解決済みプロジェクト内から対象を検索し、一致1件かつ同じ`projectIdentifier`であることを確認してから登録する。不一致なら確認まで書き込まない。
- ユーザーが同一性を確認した表記だけを別名登録する。
- 「期限未指定」は「期限なし」ではない。期限を明示されていない新規タスクは、プロジェクトIDと`deadlineOrigin: "auto"`を渡し、既定期限を適用させる。
- 相対期限の基準は、ユーザー指定の基準日時、`prepare.nextDefaultDeadlineAt`、現在のローカル日時の順に選ぶ。プロジェクトなし、または既定期限なしでは現在日時を使う。
- 選んだ基準へ相対量を適用する。「来週」は基準日時の7日後であり、既定期限がある場合は現在日時から計算しない。
- 絶対日時へ解決して`explicit`で渡す。プロジェクト既定を基準にした場合は未指定の曜日・時刻・期限種別を維持し、日時を一意に決められなければ登録前に確認する。
- `deadlineOrigin: "none"`、`--no-deadline`、期限種別`なし`は、ユーザーが期限なしを明示した場合だけ使う。

### 書込みと検証

- `update`は完全更新として、現行値と`projectIdentifier`を保持する。
- 書込み後は必ず外部から再取得し、対象件数、ID、プロジェクトID、状態、変更項目を確認する。
- 新規タスクのプロジェクト一致を確認してから後続タスクを更新する。不一致なら代替タスクを追加せず、後続更新も止めて作成済みIDを報告する。
- `prepare`が既定期限を返した期限未指定タスクは、再取得後の`deadlineOrigin`が`project-default`で、期限日時・種別が`prepare`結果と一致することを確認する。不一致なら成功と報告しない。
- 非ゼロ終了では処理を継続・再送せず、対象を直ちに読戻す。一部反映なら自動修復しない。
- 終了コード0でも標準出力が空なら成功と断定せず、読戻し結果を正とする。

### 長期タスクの分解

1. 子タスクを15～120分に分け、依存関係、完了条件、中間期限を付ける。
2. 各`identifier`を空にし、一意な`aiReferenceKey`を付け、下書き間の依存はそのキーで指定する。
3. 親と全子タスクへ解決済み`projectIdentifier`を設定する。
4. 再利用可能な冪等キーを作り、`draft-create --idempotency-key KEY --json`で登録する。
5. `draft get BATCH-ID --json`で件数、対応ID、依存関係を確認する。再送時も同じ冪等キーを使う。
6. 承認は行わず、ローカル画面の「AI下書き」へ案内する。

### 作業時間

- タイマー、自由活動、手入力、修正、延長、確認、無効化、集計は`taskctl time`を使う。
- 重複候補またはHTTP 409では再送せず、ユーザー確認後だけ`--allow-overlap`を付ける。
- 長時間ログの`要確認`は、確認、時刻修正、無効化のいずれかを選んでから処理する。

### Google Calendar

- Task Manager本体の同期は空き時間計算用の読み取り専用とする。
- ユーザーが予定変更を明示した場合は、接続済みGoogle Calendarプラグインを使う。本体の`calendar.readonly`制約をプラグインへ適用しない。

### プロジェクト情報

プロジェクト、別名、背景情報の追加・更新・アーカイブは、変更内容を提示して確認後に実行する。完全削除は行わない。
